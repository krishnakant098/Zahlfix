## Actual limits

Chromium HTTP navigation is blocked by the execution environment. Browser layout tests therefore embed the local HTML, CSS, modules and images into an in-memory fixture. This exercises the implementation's actual DOM/SVG/layout and interaction code, but bypasses network delivery, deployed CSP, cookies and the Netlify edge gate. The Node server was separately started on loopback and its HTTP bytes/headers tested. That is not an end-to-end browser/network check.

The nine-layout acceptance suite disabled WebGL to isolate the responsive DOM/SVG implementation and its fallback. A separate software-WebGL/default path smoke traversed later scenes without uncaught errors. Neither is a real-device GPU frame-pacing benchmark. Some inherited remote photography is not verified by the fixture.

Keyboard, toolbar, freeze/resume and page-transition tests intentionally inject viewport or lifecycle changes. They do not substitute for iOS Safari/Android Chrome keyboard, browser-toolbar, notch, safe-area or native BFCache tests. Zero CSS safe-area values in a headless viewport do not certify every notched device.

Login/setup HTML was generated by the unchanged GET handlers with an explicitly configured in-memory storage double, then rendered at small portrait and short landscape sizes. No real Netlify configuration, credentials or session was used.

## Corrections found during this implementation

The new numerical sweep caught potential document collisions in wide portrait tablets and short landscape; document size/projection and track separation were corrected and the final sweep is clean. An intermediate atom curl needed slightly more small-screen side clearance. A late landscape headline needed more bottom-navigation clearance. Header/menu ownership had to move out of the sticky stage so contact navigation remains available after that stage leaves the viewport. Readable fallback now clears gold-theme UI state and cannot accidentally resume the cinematic renderer.

Subpixel scroll rounding is allowed a half-pixel tolerance in ancillary-page reachability and text-mode title alignment tests; it is not hidden with a large clipping tolerance.

## Before deployment

Run the real-HTTP browser suite in a normal development environment, then verify iOS Safari and Android Chrome on physical devices, including keyboard-open contact, rotation at scene boundaries and reduced motion. Verify the full Netlify gate, CSP and inherited external assets in an isolated HTTPS staging site. Record hardware frame pacing separately.

The inherited reviewed package-lock.json requirement remains open. No runtime dependency was added and no lockfile was fabricated. npm run dev and npm run check do not require that lockfile; production/CI dependency installation does.

The source's current integrity manifest is SHA256SUMS.txt. Final delivery is extracted again, checked against that manifest and checked with npm run check. The external release-packaging report records that execution rather than claiming it from this document alone.
