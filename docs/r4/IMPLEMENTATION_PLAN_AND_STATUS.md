## Architectural ownership

- `mobile-layout.js`: sole layout profile and mobile scroll map; reparents the same contact/header/menu nodes, not copies. It restores them for desktop and readable mode.
- `mobile-r4.css`: responsive composition, safe areas, touch controls and natural contact layout. It does not redefine authentication or copy.
- `main.js`: integration, mapped scene navigation, focus settling and renderer lifecycle.
- `phase1-visuals.js`: actual measured panel geometry, shared coordinate transform and registered silhouette. Document size respects projected inter-orbit spacing; tablet collision found during the numerical pass was corrected.
- `phase1-brand.js` and `phase1-materials.js`: registered vector mask plus local optimized raster surface.
- `boot.js` / `fallback.css`: readable-mode preference, reduced motion, failure behavior and root-type fallback.
- `webgl-world.js`: uses the same profile/stage dimensions; ignores independent toolbar-only viewport shifts.
- `login.css`, `legal.css`: presentation only. Netlify request handlers are byte-identical to R3.
- `tools/serve.mjs`: optional explicitly enabled LAN host, image MIME types and clear preview errors. Default binding is loopback.

## Decisions against the proposed plan

The supplied ribbon is already the desired material master. It is integrated and optically prepared rather than generatively redesigned. Gold-background scenes use the same ribbon with an ink backing, not a separately relit illustration. The original header asset is preserved on disk; the displayed site lockup now uses the supplied ribbon in optimized sizes. The login template keeps its existing mark.

The service solution is a readable two-column internally scrolling selector with the existing active readout. It is not a swipe-only carousel. All ten options remain individually available.

The cinematic track remains for the story. On compact layouts it becomes a sticky stage in an explicitly measured track; contact follows it as normal document content. Desktop contact retains the previous presentation. Twenty narrative beats and seven scene containers remain, although contact has a different DOM parent in compact mode.

The stage uses a stable small-viewport height. Dynamic visible-viewport information is limited to focused-field access. Motion preference and reduced-motion select the complete existing text presentation rather than thinning out the content.
